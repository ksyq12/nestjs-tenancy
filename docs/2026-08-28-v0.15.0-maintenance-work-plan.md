## 0. 이 문서를 사용하는 방법

### 0.1 상태 값

| 상태 | 의미 |
| --- | --- |
| `READY` | 선행 조건이 충족되어 바로 시작할 수 있다. |
| `IN_PROGRESS` | 한 세션/브랜치가 소유하고 있다. 동시에 두 세션이 맡지 않는다. |
| `BLOCKED` | 외부 릴리스, 선행 작업, 설계 결정이 필요하다. |
| `BACKLOG` | 근거는 있으나 현재 유지보수 파동의 우선순위는 아니다. |
| `DONE` | 완료 조건과 검증 명령이 모두 통과했고 인계 기록이 남았다. |
| `DROPPED` | 근거와 결정자를 기록하고 의도적으로 폐기했다. |

작업 ID는 한 번 정하면 바꾸지 않는다. 우선순위나 순서가 달라져도 ID를 재사용하거나 번호를 당기지 않는다.

### 0.2 새 세션 시작 절차

```bash
cd /Users/ksy/Documents/GitHub/nestjs-tenancy
git status --short --branch
git rev-parse HEAD
git log -1 --oneline --decorate
node --version
npm --version
```

1. 이 문서의 기준선과 현재 HEAD 차이를 확인한다.
2. 기존 dirty 파일이 있으면 먼저 목록과 소유자를 기록하고 덮어쓰지 않는다.
3. 큐에서 `READY`인 작업 하나만 선택한다.
4. 해당 행을 `IN_PROGRESS`로 바꾸고 작업 브랜치/담당 세션/시작 HEAD를 작업 기록에 남긴다.
5. 작업 설명의 범위 밖 발견은 구현하지 말고 이 문서의 후보 목록이나 새 작업 ID로 기록한다.
6. 완료 시 검증 결과와 종료 HEAD를 기록한 뒤 `DONE`으로 바꾼다.

원격 릴리스나 PR 상태를 근거로 삼는 작업은 시작 시 다시 조회한다. 이 문서에 적힌 PR 번호와 CI 상태는 2026-08-28 시점의 스냅샷이다.

### 0.3 세션 종료 인계 형식

각 작업 아래 또는 별도 PR 본문에 다음을 남긴다.

```text
작업 ID:
상태: DONE | BLOCKED | IN_PROGRESS
시작 HEAD / 종료 HEAD:
브랜치 또는 PR:
시작 전 dirty 파일:
변경 파일:
실행한 명령과 결과:
결정 사항:
남은 위험 또는 blocker:
다음 세션의 정확한 첫 행동:
CI/릴리스 URL:
```

`BLOCKED`로 끝낼 때는 "조사가 더 필요함"으로 끝내지 않는다. 누가 무엇을 제공하면 다시 시작할 수 있는지와 재개 명령을 적는다.

### TEN-M01 — tenant 없는 inbound 경계를 fresh empty ALS로 격리

- 우선순위/상태: `P0 / DONE`
- 권장 브랜치: `codex/ten-m01-clean-inbound-context`
- 문제: `TenancyContext`의 static `AsyncLocalStorage`에 tenant 또는 explicit bypass 상태만 있다. tenant가 없는 HTTP middleware와 RPC interceptor가 handler를 그대로 호출하므로, 상위 async chain의 tenant가 inbound 경계로 상속될 수 있다. 읽기 전용 감사에서 이 상속이 실제 runtime으로 재현됐다.
- 영향: tenant가 없는 요청/메시지가 자신에게 속하지 않은 outer tenant를 관찰하거나, `failClosed`가 기대대로 작동하지 않을 수 있다.

범위:

- `src/services/tenancy-context.ts`
- `src/middleware/tenant.middleware.ts`
- `src/propagation/tenant-context.interceptor.ts`
- 관련 context/middleware/interceptor/Prisma 회귀 테스트

구현 원칙:

- `{ tenantId: null, bypassed: false }`인 내부 empty store를 도입한다.
- empty context와 `runWithoutTenant()`의 explicit bypass를 절대 합치지 않는다.
- HTTP inbound는 extraction·validation·not-found hook·`next()` 전체가 외부 tenant를 상속하지 않게 한다.
- 유효 tenant B가 확인된 뒤에만 B context를 중첩한다.
- tenant 없는 RPC Observable subscription도 empty context 안에서 실행한다.
